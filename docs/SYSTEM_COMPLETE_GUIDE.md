# 🎯 ما هو هذا النظام؟

نظام **ERP متكامل متخصص للصيدليات** يدير جميع العمليات التجارية والمالية والمخزنية. النظام مبني على تقنيات حديثة ويدعم **العملات المتعددة** مع الريال اليمني (YER) كعملة أساسية ثابتة.

### التقنيات المستخدمة:
- **Frontend:** React + TypeScript + Tailwind CSS
- **Backend:** Supabase (PostgreSQL + Edge Functions)
- **Authentication:** Supabase Auth
- **Real-time:** Supabase Realtime

### المميزات الرئيسية:
- ✅ نظام محاسبي متكامل مع GL وتقارير مالية
- ✅ إدارة مخزون بنظام FIFO مع تتبع الدُفعات
- ✅ نقطة بيع POS سريعة مع ماسح الباركود
- ✅ دورة مشتريات كاملة (PR → RFQ → PO → GRN → Invoice)
- ✅ عملات متعددة مع تحويل تلقائي للعملة الأساسية
- ✅ نظام صلاحيات متعدد المستويات
- ✅ ميزات صيدلانية متخصصة

## 2️⃣ نقطة البيع POS - 95% مكتمل

### ما هي؟
نظام بيع سريع مصمم للكاشير في الصيدلية مع واجهة مبسطة.

### ماذا تفعل بالتفصيل؟

#### 🔹 شاشة البيع الرئيسية
**المسار:** `/pos`

| العنصر | الوظيفة |
|--------|---------|
| **شريط البحث** | بحث سريع بالاسم أو الباركود |
| **ماسح الباركود** | زر لتفعيل كاميرا الجهاز |
| **شبكة المنتجات** | عرض المنتجات كبطاقات سريعة |
| **السلة** | المنتجات المختارة مع الكميات |
| **ملخص الحساب** | المجموع والضريبة والإجمالي |
| **أزرار الدفع** | دفع نقدي أو آجل |

#### 🔹 عملية البيع خطوة بخطوة
```
1. فتح جلسة POS → تحديد الصندوق والرصيد الافتتاحي
2. إضافة منتج → مسح الباركود أو بحث بالاسم
3. تعديل الكمية → +/- أو إدخال رقم
4. إضافة خصم → خصم % أو مبلغ ثابت
5. الدفع نقداً → إدخال المبلغ المستلم
6. حساب الباقي → النظام يحسب الباقي للعميل
7. طباعة الإيصال → إيصال حراري صغير
8. الفاتورة التالية → جاهز لعميل جديد
```

#### 🔹 إدارة الجلسات
**فتح جلسة:**
- تحديد الصندوق النقدي
- إدخال الرصيد الافتتاحي
- بدء العمل

**إغلاق جلسة:**
- حساب إجمالي المبيعات
- حساب الرصيد المتوقع
- إدخال النقد الفعلي
- حساب الفرق (زيادة/نقص)

## 3️⃣ وحدة المشتريات (Purchasing Module) - 75% مكتمل

### ما هي؟
وحدة إدارة دورة الشراء الكاملة من الطلب الداخلي حتى استلام البضاعة والدفع للمورد.

### دورة الشراء الكاملة:

```
┌─────────────┐    ┌─────────┐    ┌──────────────┐    ┌─────────┐
│ طلب شراء   │ →  │  RFQ    │ →  │ أمر شراء    │ →  │ استلام  │
│ داخلي (PR) │    │ عروض   │    │    (PO)     │    │ (GRN)   │
└─────────────┘    └─────────┘    └──────────────┘    └─────────┘
                                                            ↓
┌─────────────┐    ┌─────────────┐    ┌─────────────────────────┐
│   سداد     │ ←  │  فاتورة    │ ←  │ تحديث المخزون وإنشاء   │
│  المورد    │    │   شراء     │    │    طبقات FIFO          │
└─────────────┘    └─────────────┘    └─────────────────────────┘
```

### ماذا تفعل بالتفصيل؟

#### 🔹 طلبات الشراء الداخلية (PR)
**المسار:** `/purchase-requisitions`

| الحقل | الوصف |
|-------|-------|
| المستودع | أي مستودع يحتاج البضاعة |
| الأصناف | المنتجات المطلوب شراؤها |
| الكميات | الكمية المطلوبة من كل صنف |
| السبب | سبب الطلب (نفاذ، طلب عميل، موسم) |
| الأولوية | عاجل، عادي، منخفض |

**حالات الطلب:**
- `draft` - مسودة
- `submitted` - مُرسل للموافقة
- `approved` - معتمد
- `rejected` - مرفوض
- `converted` - تم تحويله لـ PO

#### 🔹 طلبات عروض الأسعار (RFQ)
**المسار:** `/rfq-requests`

| الخطوة | الشرح |
|--------|-------|
| 1. إنشاء RFQ | تحديد المنتجات والكميات المطلوبة |
| 2. اختيار الموردين | إرسال الطلب لعدة موردين |
| 3. استلام العروض | تسجيل سعر كل مورد |
| 4. المقارنة | مقارنة الأسعار والشروط |
| 5. الاختيار | اختيار أفضل عرض |
| 6. التحويل | تحويل العرض الفائز لأمر شراء |

#### 🔹 أوامر الشراء (PO)
**المسار:** `/purchase-orders`

**إنشاء أمر شراء:**
| الحقل | الوصف |
|-------|-------|
| المورد | اختيار المورد |
| العملة | عملة المورد (YER/SAR) |
| المنتجات | الأصناف المطلوبة |
| الكميات | كمية كل صنف |
| السعر | سعر الوحدة |
| الضريبة | VAT 15% |
| شروط الدفع | نقدي أو آجل |
| تاريخ التسليم | التاريخ المتوقع |

**حالات أمر الشراء:**
- `draft` - مسودة
- `sent` - مُرسل للمورد
- `partial` - استلام جزئي
- `complete` - مكتمل
- `cancelled` - ملغي

#### 🔹 استلام البضاعة (GRN)
**المسار:** `/goods-receipts`

**خطوات الاستلام:**
```
1. اختيار أمر الشراء
2. تحديد الكميات المستلمة فعلياً
3. إدخال رقم الدُفعة (Batch)
4. إدخال تاريخ الإنتاج وتاريخ الانتهاء
5. تحديد المستودع
6. الحفظ

يحدث تلقائياً:
✅ إضافة الكمية للمخزون
✅ إنشاء طبقة تكلفة FIFO جديدة
✅ تحديث حالة أمر الشراء
```

#### 🔹 فواتير المشتريات
**المسار:** `/purchase-invoices`

**إنشاء فاتورة:**
| الحقل | الوصف |
|-------|-------|
| رقم فاتورة المورد | الرقم الموجود على فاتورة المورد |
| المورد | المورد المُصدر للفاتورة |
| تاريخ الفاتورة | تاريخ إصدار الفاتورة |
| العملة | عملة الفاتورة |
| سعر الصرف | للتحويل للعملة الأساسية |
| البنود | المنتجات والكميات والأسعار |

**عند الترحيل:**
```
قيد يومية تلقائي:
مدين: المخزون (بتكلفة البضاعة)
مدين: ضريبة المدخلات (VAT)
   دائن: ذمم الموردين (إجمالي الفاتورة)

+ تحديث رصيد المورد بالعملة الأساسية YER
```

#### 🔹 سداد الموردين
**المسار:** `/supplier-payments`

| الخطوة | الشرح |
|--------|-------|
| 1. اختيار المورد | تظهر الفواتير غير المسددة |
| 2. تحديد المبلغ | المبلغ المراد دفعه |
| 3. العملة | عملة الدفع |
| 4. تخصيص الدفعة | توزيع على فواتير محددة |
| 5. طريقة الدفع | نقدي أو شيك |
| 6. الصندوق | اختيار الصندوق |
| 7. الترحيل | إنشاء قيد وتحديث الأرصدة |

## 4️⃣ وحدة المخزون (Inventory Module) - 90% مكتمل

### ما هي؟
وحدة إدارة المخزون الشاملة بنظام FIFO مع تتبع الدُفعات وتواريخ الصلاحية.

### ماذا تفعل بالتفصيل؟

#### 🔹 إدارة المنتجات
**المسار:** `/products`

| البيانات | الوصف |
|----------|-------|
| **الأساسية** | الاسم، الباركود، SKU، الوصف |
| **التصنيف** | الفئة، العلامة التجارية، المُصنع |
| **المالية** | سعر الشراء، سعر البيع، هامش الربح |
| **المخزون** | الحد الأدنى، نقطة إعادة الطلب |
| **الضريبة** | نسبة الضريبة أو معفى |
| **الوحدات** | وحدة أساسية (حبة)، وحدات فرعية (شريط، علبة) |
| **الصورة** | رفع صورة المنتج |

#### 🔹 تقييم المخزون FIFO
**الوارد أولاً يخرج أولاً**

**مثال عملي:**
```
استلام دفعة 1: 100 علبة × 400 ريال = 40,000 ريال
استلام دفعة 2: 50 علبة × 450 ريال = 22,500 ريال

المخزون الحالي:
├── طبقة 1: 100 علبة @ 400 ريال
└── طبقة 2: 50 علبة @ 450 ريال

بيع 120 علبة:
├── استهلاك 100 علبة من طبقة 1 = 40,000 ريال
└── استهلاك 20 علبة من طبقة 2 = 9,000 ريال

تكلفة البضاعة المباعة = 49,000 ريال

المتبقي في المخزون:
└── طبقة 2: 30 علبة @ 450 ريال = 13,500 ريال
```

#### 🔹 تتبع الدُفعات
**المسار:** `/batch-tracking`

| الحقل | الوصف |
|-------|-------|
| رقم الدُفعة | Batch Number من المُصنع |
| تاريخ الإنتاج | Manufacturing Date |
| تاريخ الانتهاء | Expiry Date |
| الكمية | كمية هذه الدفعة |
| المستودع | موقع التخزين |

**تنبيهات الصلاحية:**
- 🔴 منتهي الصلاحية
- 🟠 ينتهي خلال 30 يوم
- 🟡 ينتهي خلال 90 يوم

#### 🔹 إدارة المستودعات
**المسار:** `/warehouses`

| الميزة | الوصف |
|--------|-------|
| إنشاء مستودعات | تعريف مستودعات متعددة |
| تحديد المواقع | الفروع والعناوين |
| المسؤول | تعيين أمين مستودع |
| رصيد كل مستودع | تتبع الكميات في كل موقع |

#### 🔹 حركة المخزون
**المسار:** `/stock-movements`

| نوع الحركة | المصدر |
|------------|--------|
| وارد شراء | استلام بضاعة من مورد |
| صادر بيع | فاتورة مبيعات |

| مرتجع مشتريات | إرجاع للمورد |

#### 🔹 تسويات المخزون
**المسار:** `/stock-adjustments`

**أسباب التسوية:**

```

مدين: مصروفات تسوية مخزون
   دائن: المخزون

مدين: المخزون
   دائن: إيرادات أخرى
```

#### 🔹 الجرد (Stock Count)
**المسار:** `/stock-count`

**خطوات الجرد:**
```
1. إنشاء جلسة جرد → تحديد المستودع والتاريخ
2. طباعة قائمة الجرد → قائمة بالمنتجات
3. العد الفعلي → موظفو المستودع يعدون
4. إدخال الكميات → إدخال الكمية الفعلية لكل صنف
5. حساب الفروقات → النظام يقارن الفعلي بالمسجل
6. إنشاء تسويات → تسوية تلقائية للفروقات
```

## 5️⃣ وحدة المحاسبة (Accounting Module) - 95% مكتمل

### ما هي؟
النظام المحاسبي المتكامل الذي يدير دليل الحسابات والقيود اليومية والتقارير المالية.

### ماذا تفعل بالتفصيل؟

#### 🔹 شجرة الحسابات
**المسار:** `/chart-of-accounts`

**الهيكل:**
```
1000-1999: الأصول
├── 1100: الأصول المتداولة
│   ├── 1110: النقدية والبنوك
│   ├── 1120: ذمم العملاء
│   └── 1130: المخزون
└── 1500: الأصول الثابتة

2000-2999: الخصوم
├── 2100: الخصوم المتداولة
│   ├── 2110: ذمم الموردين
│   └── 2120: ضريبة مستحقة
└── 2500: الخصوم طويلة الأجل

3000-3999: حقوق الملكية
├── 3100: رأس المال
└── 3200: أرباح محتجزة

4000-4999: الإيرادات
├── 4100: إيرادات المبيعات
└── 4200: إيرادات أخرى

5000-5999: المصروفات
├── 5100: تكلفة البضاعة المباعة
├── 5200: مصروفات إدارية
└── 5300: مصروفات تشغيلية
```

#### 🔹 القيود اليومية
**المسار:** `/journal-entries`

**قيد يدوي:**
- تاريخ القيد
- الوصف/البيان
- أسطر متعددة (حساب + مدين/دائن)
- التحقق من التوازن (مجموع المدين = مجموع الدائن)
- مركز التكلفة (اختياري)
- المرفقات

**القيود التلقائية:**
| المصدر | القيد |
|--------|-------|
| فاتورة مبيعات | مدين عملاء / دائن إيرادات + ضريبة |
| فاتورة شراء | مدين مخزون + ضريبة / دائن موردين |
| تحصيل عميل | مدين نقدية / دائن عملاء |
| سداد مورد | مدين موردين / دائن نقدية |
| تسوية مخزون | مدين/دائن مخزون مقابل مصروف/إيراد |

#### 🔹 دعم العملات في GL
**كل قيد يحفظ مبلغين:**
```
amount_fc = المبلغ بعملة المعاملة (Foreign Currency)
amount_bc = المبلغ بالعملة الأساسية YER (Base Currency)

مثال:
فاتورة بـ 1,000 SAR وسعر الصرف 66.50:
├── debit_fc: 1,000 SAR
├── debit_bc: 66,500 YER
├── credit_fc: 1,000 SAR
└── credit_bc: 66,500 YER

جميع التقارير المالية بالريال اليمني (BC)
```
